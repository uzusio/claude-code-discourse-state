# intent-board

Claude Code が「あなたの指示をどう読んだか」を、会話しながら画面に出す拡張（mod）。

あなたが**言ったこと**と、Claude が**補ったこと**を分けて表示するので、読み違いに作業が始まる前に気づけます。

## 解決したいこと

コーディングエージェントに作業を任せると、指示の字面とは合っているのに、組み上がった手順がずれていることがあります。原因の多くは、エージェントが黙って補った前提です。たとえば次のようなもの：

- 範囲：「全部」と言ったのに、ある条件のものだけを対象にした
- 順番：「最後に確認して」と言ったのに、確認を先に回した
- 理由：言っていない理由で手順を組み替えた

こうした前提は返信の中に埋もれていて、ずれに気づくのはたいてい成果物ができてからです。

intent-board は、補った前提を理由つきで常に見える場所に出します。気づいたらその場で「それは言ってない」と止められます。

## 見え方

**プロンプトの上の帯**（常に表示）

```
意図：Claude の意図の汲み取り方を会話中に見せ、ずれを作業前に止める
補った前提 3件 ｜ 問い 2件 ｜ 更新あり  [ボードを開く]
```

**ボード**（帯のボタンか `/intent-board` で開閉。Esc でも閉じる）

```
目的：Claude の意図の汲み取り方を会話中に見せ、ずれを作業前に止める
要確認：補った前提 3件
  ▸ それより前 14件
  C27 次のループ時刻は会話記録の末尾から拾う
      理由：ユーザーは拾い方を指定していない
問い
  ▾ ○ Q6 ステータスラインに次のループ時刻を出せるか（決める人：ユーザー）
      C26 スクリプト側で出す
  ▸ ✓ Q2 ダッシュボードをどこに置くか（決定 1件）
▸ 置き換わったこと 2件
いまの手順
  1. ペインを木にして、最初はたたむ  ← goal・C30
```

- 補った前提は黄色で、新しいものだけ開いて表示する
- 会話は「目的 → 問い → 決まったこと」の木で表示する。片付いた問いはたたんでおく
- 訂正された決定は消さずに「置き換わったこと」に残す

## 言語学からの着想

会話の構造を扱う、談話意味論の2つの枠組みを縮めて使っています。

- **SDRT**（Segmented Discourse Representation Theory, Asher & Lascarides）：発話どうしの関係（訂正・補足・追加・回答など）を明示する。intent-board では、関係ラベルを状態の更新規則として使う。たとえば「訂正」なら前の決定を取り消して置き換え、その決定に依存していたものを見直す
- **QUD**（Question Under Discussion, Roberts）：会話を「いま議論している問い」の木として捉える。ボードの「問い」の木はこれに当たる
- **accommodation**（前提の補完, Lewis）：聞き手が、相手の言っていない前提を補って解釈を成り立たせること。読み違いはたいていここで起きる。ボードの「補った前提」はこれを可視化したもの

## しくみ

Claude の返信が終わるたびに、次の3段で状態を更新します。

1. **読み取り**（sonnet）：そのターンのあなたの発言と、Claude の返信・作業を読み、状態への差分を作る
2. **判定**（haiku）：「あなたが言ったこと」に分けた項目が、発言に本当に書かれているかを確かめる。書かれていなければ「補った前提」に回す
3. **検証**（コード）：存在しない決定の取り消し、依存の放置、理由のない補完などを弾き、通った差分だけを記録する

記録はセッションごとに、ローカルの一時フォルダ（`<TEMP>/discourse-state/<セッション id>/`）に置きます。

## 使い方

Claude Code 2.1.289 で動作を確認しています（mod の仕組みが使える版が必要）。

```sh
git clone https://github.com/uzusio/discourse-state
claude --plugin-dir discourse-state/mod/intent-board
```

1ターンごとに、読み取りと判定でモデルを2回呼びます。目安は sonnet が入力 3〜4k・出力 1〜2k トークン、haiku が 0.5k トークンほどです。

## 開発

```sh
cd poc && python -m unittest test_discourse_state          # 状態の更新規則（Python 版・仕様）
cd mod/intent-board && claude plugin validate . && claude plugin test .
```

`poc/` の Python 版と `mod/` の TypeScript 版が同じ結果を返すことを、共通の例（`poc/examples/audit_job.jsonl`）で確かめています。例を変えたら `python poc/export_fixture.py` を実行してください。
