# claude-code-discourse-state

Claude Code が**あなたの意図をどう読み、それをどんな作業の流れに落としているか**を、会話しながら画面に出す拡張（mod `intent-board`）。

いわば Claude の頭の中の「いまの理解」を、あなたがいつでも覗ける状態にします。指示の一つひとつではなく、意図が合っているかを確かめながら作業を任せられます。

## 解決したいこと

コーディングエージェントとの会話は、どうしても「指示」のやり取りになります。でも本当に合わせたいのは指示の字面ではなく、その奥の意図です。意図さえ合っていれば、手順や流れはエージェントに任せられます。

ところが、エージェントが意図をどう読んだかは、作業の結果が出るまで見えません。指示の字面には合っているのに、組み上がった流れがずれている。それに気づくのはたいてい成果物ができてからです。

intent-board は、エージェントの**意図の読み**と、その読みから組んだ**流れ**（各手順がなぜその手順なのか）を常に見える場所に出します。やり取りが非同期に進んでいても、見たいときにボードを開けば読みのずれを見つけられ、「そうじゃない」と言えば次のターンでボードに反映されます。

ずれの原因になりやすい**文脈の補完**（あなたが言っていない範囲・順番・理由をエージェントが補ったもの）は、黄色で区別して示します。

## 見え方

![意図ボード（例のデータ）](docs/board.svg)

上がボード（帯のボタンか `/intent-board` で開閉。Esc でも閉じる）、下の2行がプロンプトの上に常に出る帯です。画像は例のデータを mod と同じ並びで描き出したもの（`npx tsx tools/render-svg.ts`）。

- 意図の読みは、あなたの言葉（薄い字）と Claude の読み（太字）を並べて出す
- 監査役の指摘（Claude の作業とボードの食い違いなど）は赤で出す
- 流れの各手順に、なぜその手順か・どの意図から出たかを添える。文脈の補完に乗っている手順には、それを黄色で添える
- ボードの表示に「そうじゃなくて〜」と言えば、次のターンで読みや決まったことが直る
- 決まったこと・文脈の補完・置き換わったことは参照用としてたたんでおく。訂正された決定は消さずに「置き換わったこと」に残す

## 言語学からの着想

会話の構造を扱う、談話意味論の枠組みを縮めて使っています。

- **QUD**（Question Under Discussion, Roberts）：会話を「いま議論している問い」の木として捉える。意図の読みを根に、問いと決まったことを木で持つ
- **SDRT**（Segmented Discourse Representation Theory, Asher & Lascarides）：発話どうしの関係（訂正・補足・追加・回答など）を明示する。関係ラベルを、読みの更新規則として使う。たとえば「訂正」なら前の決定を取り消して置き換え、その決定に依存していたものを見直す
- **accommodation**（前提の補完, Lewis）：聞き手が、相手の言っていない前提を補って解釈を成り立たせること。読みがずれる原因になりやすいので、「文脈の補完」として黄色で区別して示す

## しくみ

ボードを書くのは、あなたと話している Claude 本人です。別のモデルが会話を外から読んで書くのではないので、ボードは Claude の理解そのものになります。

1. **書く**（Claude 本人）：意図の読み・流れ・決まったことが変わったターンの終わりに、mod が用意したツール（`board_update`）で差分を渡す
2. **検証**（コード）：存在しない決定の取り消し、依存の放置、理由のない補完などを弾く。崩れていればツールの結果として突き返し、Claude がその場で直す
3. **監査**（別のモデル、ターンの終わりに自動）：ボードは書き換えず、指摘だけを赤で添える
   - 出どころ（haiku）：「あなたが言ったこと」として書かれた項目が、あなたの発言に本当にあるか
   - 食い違い（sonnet）：そのターンの Claude の返信や作業が、Claude 自身の書いたボードと矛盾していないか

作業をしたのにボードを更新しなかったターンは、帯に「ボード未更新」と出て、次のターンで Claude に促します。ボードの中身を Claude に差し込むことはしません（別のモデルの読みを正本として読ませると、読み違いが固まり、Claude の判断がその要約に引っぱられるため）。

記録はセッションごとに、ローカルの一時フォルダ（`<TEMP>/discourse-state/<セッション id>/`）に置きます。

## 使い方

Claude Code 2.1.289 で動作を確認しています（mod の仕組みが使える版が必要）。

```sh
git clone https://github.com/uzusio/claude-code-discourse-state
claude --plugin-dir claude-code-discourse-state/mod/intent-board
```

作業のあったターンごとに、監査でモデルを1〜2回呼びます（食い違いの確認に sonnet、出どころの確認に haiku）。加えて Claude 本人がボード更新のツールを呼ぶぶんのトークンがかかります。

## 開発

```sh
cd poc && python -m unittest test_discourse_state          # 状態の更新規則（Python 版・仕様）
cd mod/intent-board && claude plugin validate . && claude plugin test .
```

`poc/` の Python 版と `mod/` の TypeScript 版が同じ結果を返すことを、共通の例（`poc/examples/audit_job.jsonl`）で確かめています。例を変えたら `python poc/export_fixture.py` を実行してください。
