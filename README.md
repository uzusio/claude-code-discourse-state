# discourse-state

会話の中で、Claude がユーザーの意図をどう汲み取っているかを見えるようにする Claude Code の拡張（mod）。

誤読はたいてい、ユーザーが言ったことではなく、Claude が**補ったこと**の側で起きる。このリポジトリは、その境目を会話しながら画面に出し、ずれた読みを作業が走る前に止められるようにする。

## 意図ボード

| 項目 | 中身 |
|---|---|
| ① 目的 | ユーザーの言葉の引用と、その読み |
| ② 決まっていること | ユーザーが言った・認めたこと |
| ③ 置き換わったこと | 訂正で取り消された決定と、その置き換え先 |
| ④ 補ったこと | ユーザーが言っていないのに Claude が置いた前提（理由つき・色つき） |
| ⑤ 意図 → いまの手順 | 各手順がどの意図から出てきたか |
| ⑥ 開いている問い | まだ決まっていないことと、決める人 |

プロンプトの上の帯に要約（目的・補った前提の数・問いの数）、ペインに全体を出す。`/intent-board` でも開ける。

## しくみ

会話の状態は SDRT（談話関係）と QUD（議論中の問い）を縮約したもの：関係ラベル8種を状態の更新規則として使い、問いはスタックで持つ。意図ボードはこの状態の見え方で、別の状態は持たない（② と ④ は同じ決定を「誰が言ったか」で分けるので重ならない）。

ターンが終わるたびに：

1. **読み取り**（sonnet）：そのターンのユーザーの発言と Claude の返信・作業から、状態への差分を作る
2. **判定**（haiku）：「ユーザーが言ったこと」に分けた項目が発言に本当に書かれているかを確かめ、書かれていなければ ④ に回す
3. **検証と適用**（コード）：存在しない決定の取り消し、依存の放置、理由のない補完などを弾き、通った差分だけを差分ログに足す

差分ログ（`<一時フォルダ>/discourse-state/<セッション id>/diffs.jsonl`）が正本で、状態とボードはそこから作り直す。消費は同じ場所の `usage.jsonl` に残る。

## 構成

- `mod/intent-board/` — Claude Code の mod
  - `hooks/state.ts` — 状態の検証・更新・ボードの導出（純粋関数）
  - `hooks/parse.ts` — 読み取りと判定のプロンプト、返答の解釈
  - `hooks/board.ts` — 帯の表示
  - `hooks/register.tsx` — イベントへのつなぎ込みと描画
- `poc/` — 状態の検証・更新の Python 版（仕様）。`examples/audit_job.jsonl` で TypeScript 版と同じ結果になることを確かめる（`python export_fixture.py` → mod のテスト）

## 開発

```sh
cd poc && python -m unittest test_discourse_state
cd mod/intent-board && claude plugin validate . && claude plugin test .
```
